# Host verifier wire v1

`schema.json` is the only handwritten wire data-shape source. Run `node scripts/generate-host-verifier-protocol.mjs --write` to regenerate, and `--check` to verify checked-in TypeScript/Rust output. Semantic checker IDs/revisions are implemented by the Rust library; the kernel separately declares required checks. A wire schema is not a JavaScript semantic oracle.

## One owned process, one attempt

The Node Effect service starts the packaged target binary without a shell and with an empty environment. It sends JSON-RPC 2.0 `initialize` (`protocol`, `schema_digest`, `build_id`), verifies the matching `Hello`, then sends exactly one `analyze` request with `Job`. The child returns one matching `Report` and exits. There is no socket, background service, modeld call, runtime Cargo build, executable download or alternate-parser fallback.

Frames are UTF-8 JSON preceded by exactly `Content-Length: <positive decimal byte count>\r\n\r\n`. Maximum header is 128 bytes and maximum body is 65536 bytes. Length is bytes, not characters. Duplicate members, malformed UTF-8/JSON, extra or truncated headers/bodies, unexpected RPC IDs, duplicate final responses and extra output fail the attempt. Standard output is protocol-only; standard error is bounded diagnostics and must not contain source snippets, paths or credentials. The current binary emits no progress notifications.

The report is accepted only after complete framing, shape and cross-field validation, exact job/attempt/artifact/checker/build identity, successful process exit and `close`. An apparently valid response followed by nonzero exit is not a valid result. Required checks not implemented at the requested revision fail admission; unsupported semantic shapes remain explicitly unsupported.

## Read-only descriptor capabilities

A job passes source bytes through inherited descriptors 3–5, never through paths or large JSON strings. Node copies caller buffers into private temporary files, reopens them read-only and unlinks the directory entries before spawning. The child admits only unique read-only regular descriptors, checks byte budgets, before/after file identity and SHA-256, and decodes strict UTF-8. Source, actual transformed candidate and companion are distinct roles. No candidate means the requested candidate predicates are unsupported, not passed. The original and candidate are supplied by the existing TypeScript exact-apply owner; Rust never applies a second transformation.

At most three artifacts, each 64 MiB and at most 128 MiB combined, are admitted by Node. The Linux binary constrains address space, CPU time and core dumps. A descriptor alone is not claimed to be immutable: both sides check the actual bytes. No source file is evaluated as JavaScript.

## Cancellation and cleanup

The parent owns cancellation: terminate the owned child, escalate to KILL after the finite grace period, and wait for its pipes/process to close before releasing descriptors and the single-flight slot. A finite cleanup failure is `cleanup-unconfirmed` and quarantines the slot rather than allowing another child. Linux parent-death signaling terminates a child left after a hard parent crash. Cancellation is a failed analysis, never evidence that the Host is broken or repaired.

The current v1 implementation uses process termination for cancellation, not a cooperative JSON-RPC cancellation notification. No active analysis can perform native effects or publish application health by itself. The Server's source lane is independent, so an exact recipe mismatch can enter the original OBS incident transaction before analysis completes or while the verifier is unavailable.

## Evidence and conformance

`cases/shapes.json` is an independently authored common shape corpus consumed by Node and Rust tests. It checks wire structure only. Semantic cases live under `test/fixtures/host-verifier` and Rust semantic tests; expected predicates are not regenerated by the matcher or schema generator. Real Node tests additionally cover framing, IDs, writable/mismatched descriptors, duplicate finals, response-before-close, cancellation, abnormal exit and parent death.

Static evidence does not assert loaded Host generation, handler attachment, exercised behavior, current ownership or permission to repair/run. Public management DTOs contain no descriptors or AST nodes. Domain semantics remain in `packages/runtime-kernel/src/host-health.ts`; the implementation and remaining qualification obligations remain in `docs/tickets/HOST-01-patch-health-verifier.md`.
