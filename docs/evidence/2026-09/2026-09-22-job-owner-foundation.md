# Job owner extraction and safety identity

CLI-05 W3. The original governed filesystem, process authority and Job manager move from CLI daemon implementation to the Box runtime IO owner. Existing filesystem and Job consumers use the moved code, not compatibility forwarding files or a second execution engine. The management entry migration follows this foundation; this report does not declare the old Job transport retired.

The Job owner now holds the existing Linux advisory gate for its ledger lifetime. Competing services cannot independently recover and dispatch the same history. Stored execution identities no longer expire with the previous diagnostic retention threshold: a full safety-record inventory refuses new admission rather than erasing unknown effects or accepting the original ID again. Malformed or unsupported records are preserved and block acquisition, instead of being overwritten with fabricated unknown rows. Valid prior-generation queued/running records become unknown, without execution replay. Missing log details do not reset historical offsets. State publications serialize per Job, and uncertain admission publication keeps the identity occupied rather than recursively removing its directory.

This is not a sandbox, recovery of arbitrary whole-installation rollback, or a guarantee that all descendant OS effects end with the leader. The existing literal argv, named-root descriptor, executable policy, bounded output, signal identity and cancellation owner remain. No live job, Host or service is changed.

Verification at this intermediate source: repository Bun 1.3.14, root typecheck; 77 tests across 7 files passed with zero failures (`test/job-safety-store.test.ts`, Job/filesystem/mutation/event/detail consumers, including the matched Box event suite). The former expectation that corrupt state is rewritten was removed; dedicated counterexamples assert byte preservation. Shared management contracts are not counted as integrated behavior here. Final managed Server/CLI/Web and installed candidate evidence belongs to the subsequent work package.
