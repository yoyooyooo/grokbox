# Evidence：历史证据与主题提炼

这里统一保存已经发生的实验、集成、审查及设计演变证据。按日期阅读固定窗口，按主题追溯机制和取舍；二者共用一个根目录，不再要求读者区分 reports 与 archive。

| 入口 | 用途 |
| --- | --- |
| [2026-09 固定窗口](2026-09/README.md) | 保留原日期、来源版本、动作、成功/失败、未观测项和准确证据范围 |
| [主题提炼](topics/README.md) | 串联跨窗口的机制、替代方案、反例和可复用教训 |

## 使用边界

证据回答“当时为什么这样判断”，不直接回答“现在是否可以执行”。当前合同由 [Documentation](../README.md) 路由；实施计划在 [Roadmap](../roadmap/README.md) 和来源票；现场已验/未验只看 [LIVE](../tickets/LIVE-integration-validation.md)。历史 source SHA、测试计数或成功回执不授权新版本、新身份或新副作用。

固定窗口使用 `YYYY-MM/YYYY-MM-DD-主题.md`；跨窗口提炼使用 `topics/主题.md`，必要时在文件名附研究月份。不要仅为对称创建空月份或大量子分类。新窗口另写证据，不覆盖旧实验结论；纠错注明原事实及补证来源。

## 独立 POC 如何归入项目证据

不要把临时项目整个拷入公开仓库。提炼目标、输入与真实调用链、模型/身份/状态的 owner、最小变换、原生复用、成功与反例、未知范围、可移植合同和原始材料定位。文件仍在独立目录使用，与其思想和证据已归档并不矛盾。

本机路径不自动等于秘密。优先使用仓库相对路径、证据根变量和相对文件名；确有复盘价值时保留明确标注的本机位置。凭据、令牌、认证头、私人聊天正文、个人信息和非公开 Host/App 源码不进入公开证据。源码摘要、协议角色、脱敏结果和算法说明可以保留；可读的原始材料与公开提炼是两个层次。

归档不等于删除许可：仍有 import、活动实验或未决效果的资产继续保留。先确认正式替代、原始证据保全及消费者去依赖，再清理临时资产；Bot/Memory/原生数据库不属于文档迁移范围。

## 旧路径追溯

当前文档链接统一指向本目录。对于 `git show <固定提交>:<旧路径>` 这样的历史定位，保留那个提交真实存在的路径，不能按现役目录机械改写。Git 路径重命名记录用于关联迁移前后；不保留两份可继续追加的历史正文。
