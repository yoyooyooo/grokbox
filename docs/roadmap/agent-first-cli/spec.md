# Agent-first 命令、架构重建与 Web UI 交付 spec

状态：端到端目标、架构骨架、核心能力及一次性采用边界已接受；实施已开始，首个模型域切片进展见 [CLI-05](../../tickets/CLI-05-implementation-follow-through.md)，精确公共合同和完整交付仍待推进。完整候选在[合同](command-contract.md)和[目录](command-catalog.md)，[决策清单](decisions.md)区分已确认目标与未决细节；当前实现仍需按源码与[产品合同](../../product-contract.md)核对。

## 问题

grokbox 的命令按既有实现逐步累积。调用者需要识别 daemon、modeld、monitor、runtime 等内部边界，多个状态入口的观察范围不同，部分流程还把阶段推进交给调用方。直接把这些入口包成 HTTP，会把实现分裂带到 Web UI。

主要使用者是原生 Bot 和代表用户工作的 Agent。命令收束应反推能力边界、事实归属和可靠执行，允许重写既有架构，不以保留旧模块为前提。Agent First 落在能力、命令和参数的表达上；Bot 的业务分工和工具使用策略由调用者决定。

CLI 合同是此次工作的前置环节，整体目标一路覆盖架构重建、已有必要能力收束、Web UI、安装交付与验收。规划固定核心方向、边界、责任和故事，不预先指定每个包名、接口字段或页面组件；实施者按这些边界细化。

功能工程与视觉定稿分开推进。CLI、Server、领域模块、数据能力及 Web 工程按生产使用要求建设；Web 可先采用朴素的真实功能原型，路由、请求、权限、状态、订阅及操作恢复准备长期保留，不是以后推倒的假数据演示。视觉尚未定稿，不阻塞这些能力，也不因功能原型通过就宣称最终视觉已交付。

## 产品边界

grokbox 提供原生 Bot 管理、自定义模型、消息与原生协作、Memory/Project/文件、持续观察和系统维护等基础能力。谁创建谁、何时调模型、怎样分工和完成业务任务，不成为 grokbox 的内置使用策略。原生已有的 Group、消息、Routine 能力仍可暴露；不新增通用业务任务、DAG 调度系统或第二 Agent loop。

保护与交接是明确的产品责任：用户应尽量无需操心官方所有权变更后的重建与交接。grokbox 负责后台推进，但自动化范围必须来自实际证据与已验证能力，不能把完整交接愿景当成已有实现。

主要工作面仍为单 Box。保留已有可工作的外部能力及其真实范围，不扩为网络产品管理平台。一个公共 `grokbox` CLI，`gbox` 为完全等价的别名。

## 已接受的架构骨架

| 边界 | 职责与寿命 |
| --- | --- |
| CLI | 面向 Agent 暴露完整、可发现、可组合的基础能力；普通业务调用统一管理服务 |
| 共享合同与客户端 | 统一目标、输入输出、错误、操作回执及事件语义；CLI 和 Web 共用，不承载第二套领域规则 |
| 领域模块与适配 | 管理服务内的领域模块拥有管理用例与规则；原生/存储适配封装 Gateway、Host、文件和数据库 |
| 常驻管理服务 | 独立的 Effect v4 beta、Effect-first 服务；内部模块/worker 负责采集、证据、索引、异常、保护、交接和通知，各自有故障与资源边界 |
| modeld | 保持独立进程；管理服务重启不主动终止已开始的合法执行，也不因此绕过新工作的实时资格检查 |
| 官方 Host | 继续承担原生 Bot 执行；原生适配维持轻量边界，不另造一套 Agent loop |
| Web UI | MonoRepo apps 子项目，TanStack Start；SSR 只负责页面预取与渲染，业务 API 独立，和 CLI 共用后台用例 |

普通业务没有服务故障时的隐式直连 fallback。服务 bootstrap/生命周期、离线诊断、Box 外部唤醒与恢复保留明确入口与独立可用的恢复路径。具体回执定位仍由合同票收口。

Web UI 复用领域能力与合同，不通过执行 CLI 子进程获得业务能力。页面可以有展示逻辑和聚合查询，但模型选择、保护、源数据修改等规则只有一套。CLI 命令树不决定后端模块划分；内部模块也不自动拆成独立服务或大量小包。具体包名、目录、schema 和路由留给实施。[重建骨架与工作链路](implementation-impact.md)拥有跨领域的实施组织。

统一服务不等于统一所有数据的权威。原生数据、模型配置、执行记录、恢复材料及观察历史分别保留事实 owner；观察投影与搜索索引可重建，不能把新版运行产生的必要历史都当作缓存。旧开发期数据的兼容范围见下文。

## 已接受的核心能力

### 真实 Bot、保护与交接

主要对象仍是原生 Bot。替换中的 A 和 B 各有真实身份，grokbox 保存保护记录、恢复材料、前后继关系和交接进度；不另设跨工具唯一人格、身份规则或专属 Memory 身份层。

所有确认属于 Box 的 Bot 默认开启观察与恢复材料保全，允许逐 Bot 调整或关闭。确认官方所有权丢失后，后台负责按有效策略推进重建和交接；超时、断连、来源陈旧本身不能触发“归属已丢失”的判断。

恢复目标优先使用原生 checkpoint 等可靠材料。完整恢复不可行时，只有降级路径本身也有证据与原生能力支撑，才可利用 Memory、历史摘要等恢复可用性，并披露缺口。能否继续工作、迁移关系和退役旧 Bot 分别核验；新 Bot 可用不等于交接完成。

确定性程序负责可验证步骤与结果核验；Bot 可协助语义理解和交接，但其判断不能替代执行回执。缺关键事实或能力时保留 blocked/unknown/未完成，独立且有依据的部分可继续。旧 ref 不自动改指继任者。

### 观察记录与全局检索

后台持续采集并保存必要的状态快照、变化记录与来源证据，CLI/Web 共享当前视图和历史查询。无页面打开时仍运行；断流、陈旧、未知和覆盖缺口必须可见，不补造未采集的历史。

在已授权、已接入的 Memory 与 Project 文件范围内，支持跨来源搜索与原位置定位。索引是派生数据，不接管原内容；agent/user/project scope、同步延迟与内容来源分别保留。来源缺失不能显示成“全局无结果”。

### 模型选择

Bot 明确选择原生模型、跟随 grokbox 默认模型，或指定模型。跟随默认是一种选择关系，不是假模型条目。只有选择跟随的 Bot 才受全局默认切换影响；显式指定模型即使恰好等于当前默认值，也不转为跟随。

指定模型引用集中维护的模型配置。配置更新作用于后续轮次，每轮记录实际采用的配置版本；普通配置变更不改写在途轮次的捕获事实。此范围适用于支持 grokbox 模型接管的 Box-owned Bot，不限定为 grokbox 创建的 Bot。拒绝删除仍被 Bot 选择或全局默认引用的模型；仍有 Bot 跟随时拒绝清空默认，并返回引用关系。调用者先显式换绑或回原生，再删除/清空；不擅自换模型。引用检查的并发与精确错误合同仍需细化，历史执行事实独立保留。

### 数据管理与 Web UI

Memory、Project 与文件纳入读取、检索和修改的基础能力范围。每个来源只有明确写入路径和结果核验后才开放相应修改；无法可靠写入的来源保持只读。接受写能力范围不等于批准对称全套 CRUD，也不允许直写派生索引冒充源数据已更新。

Web UI 以内部观察为主，提供模型配置、保护设置、文件管理、异常处理等必要管理操作，与 CLI 共用用例。CLI 的完整命令面不必逐项映射为页面按钮。首版无 Bot 对话、业务任务发起或代官方客户端回复审批。

[V0 视觉](../../design/webui/v0/README.md)保留为可继续推敲的参考，不是冻结的设计或功能施工门槛；截图功能服从[页面目标](../future/webui-console.md)。信息架构、对象关系和必要交互先接真实能力，配色、布局、组件造型与动效后续定稿。[固定研究](../../reports/2026-09-19-webui-source-feasibility.md)保存有边界的可行性证据，不是实现验收。

### 管理异常与通知

后台根据合格事实主动识别、记录并跟踪所有权变更、保护交接受阻、模型执行故障、观察中断等管理异常。异常的发生、变化和恢复可追溯；已查看/忽略与真实恢复不同，原生 alert、持久 incident 和通知投递结果分别呈现。

调用者配置接收目标并显式启用通知后，后台承担持续投递、去重、有限重试和投递记录，无需外部 Agent 常驻驱动。未知投递先对账，不能因重试策略而盲目重发。通知范围围绕管理事实，规则不接管 Bot 的业务任务判断。测试是独立、显式、可选的操作；完成必要配置与授权后可以启用，不强制先通过测试或要求人工声明已收到。启用状态、测试结果与实际投递分别记录，具体测试输入和回执待细化。

## 核心故事与合同走查

| 故事 | 必须守住的结果 |
| --- | --- |
| 陌生 Agent 使用工具 | 按需发现能力、定位明确目标、组合基础操作，不必学习 worker/数据库布局 |
| 调整模型并遇到断连 | 找回原操作；区分选择关系、配置提交与某轮实际采用 |
| 查看 Bot 与全局材料 | 当前视图可接续事件，历史与检索保留来源、新鲜度及缺口 |
| 修改 Memory/Project/文件 | 经真实源 owner 修改并核验；CLI/Web 并发冲突不静默覆盖 |
| 归属被官方回收 | 默认保护提供材料，后台按证据推进继任与交接；外部 Agent 主要处理明确例外 |
| 管理异常与通知 | 后台持续跟踪，启用后主动投递；确认看过不伪装恢复 |
| 管理服务或 Box 不可达 | modeld 保持独立寿命，恢复入口不依赖已故障的业务服务 |
| 切换新命令面 | 一套正式命令与实现，既有必要数据和能力有明确去向 |

[命令合同](command-contract.md)保留进一步的调用旅程。它们用于检验工具语义，不要求用户按某套业务编排方法使用 Bot。

## 破坏式切换

用户明确说明项目尚未正式发布，并期望借此次破坏式重建把架构收干净。采用直接切换：新命令合同定版后，同批迁移仓内脚本、Skill、文档、测试及已知调用方，旧语法退出，不设置对外兼容期或长期别名层。`gbox` 作为既定等价入口保留。

最终交付仍是完整新版，开发中允许未采用的中间版本不完整或不可用，不要求零停机、新旧双轨或临时兼容层；可以重排包结构、替换模块和删除旧入口后接通整条链路。2026-09-22 用户调整采用顺序：运行核心先达到完整质量并经过独立范围验收，随后可逐 Bot 切模型日用；其余管理能力与自有 Web 并行完成。最终只有一套正式语义和有效 writer，不另建轻量版或保留旧执行兼容。映射按原意图、参数分支与结果核验，不只统计命令名。

不先跑完旧版本 LIVE 再允许重建，也不把每个提交当一次发布或现场采用。实施期间按变化做针对性检查，及早验证关键原生能力和目标服务宿主；失效的旧语法/结构测试明确迁移或退役，仍成立的数据与恢复不变量继续验证。运行核心候选和全产品候选分别完成适用的整体检查、实际制品、独立审查及真实验收；前者不等待全产品 W3 结束。施工期可用性不是门槛，已采用核心的上下文连续性、数据保护、幂等、重启恢复及运行/开发制品隔离仍是硬要求。

### 运行核心采用与完整交付分开

运行核心的用户结果是：在同一原生 Box Bot/会话中切换原生与合格自定义模型，工具、正常续聊、Memory/episode、长上下文 compact/overflow、checkpoint、原版 Grok Bot App 和重启/官方退出均可靠。先完成采用前资格和可执行恢复方案，再允许受控切换 Host/modeld 取真实证据；完成核心工程验收、至少24小时有界持续运行和用户对该范围的确认，才开始日常吃狗粮。不能以短对话、单模型、原版 App 未验或用户代测降低质量。

自有 Web 的完整功能/视觉、原生材料管理写入口和全局检索、完整替身/关系交接/退役及其他管理命令可以后置；它们仍是全产品义务。核心实际经过的原生数据安全、默认观察/必要保全、已启动 worker、加载补丁和已启用副作用必须纳入风险闭包，未验能力由真实权限/配置隔离，不擅自关闭必要保护或仅隐藏页面。

[并行交付拓扑](parallel-delivery.md)固定路线与 J0–J5 汇聚点，[核心 LIVE 集合](../../tickets/LIVE-integration-validation.md#core-runtime-lane)固定采用判据/结果；它们不取代领域来源票。J4 是 W3 内的核心日用节点，不是全产品 W4/W5 完成。采用后使用固定不可变安装制品，v2/工作树继续施工不自动覆盖现役；后续升级按实际变化复验，正式发布另行授权。

### 数据兼容范围

| 数据 | 此次重建要求 |
| --- | --- |
| 官方 Bot、Memory、Project 与原始文件 | 继续接入原有数据及身份，不因内部重建而重置 |
| 有价值的模型、连接等配置 | 按需一次性转换或导入，不建设通用历史版本迁移框架 |
| grokbox 开发期内部数据库、历史日志、操作回执和测试状态 | 不承诺迁入新版，不让这些旧结构约束新架构 |
| 新版观察投影与搜索索引 | 从真实来源重新建立，明确新历史的起点和覆盖缺口 |

不承诺导入不等于自动删除源数据、凭据或旧状态。本轮仅确定兼容范围，不执行清理。实施接入时仍需识别在途或结果未知的外部效果，避免重复执行；新系统产生的回执、保护材料和必要历史继续按各领域持久化与保留合同管理。

## 本轮交付与剩余工作

本轮将已确认方向写入端到端规划、[迁移映射](migration-map.md)与来源票。命令名、参数、状态枚举、退出码、期限、部分准入与恢复协议仍待实施前细化，不能因文档存在就视为已验证。

[CLI-01](../../tickets/CLI-01-discovery-and-targeting.md)至 [CLI-04](../../tickets/CLI-04-command-cutover.md)负责合同差额。[CLI-05](../../tickets/CLI-05-implementation-follow-through.md)拥有跨域重建、核心采用汇聚、旧边界退出与最终完整交付；[T29](../../tickets/T29-runtime-webui.md)拥有共享 API 和真实 Web UI，T41/CONT/模型等来源票保留领域差额。Web UI 仍在整体交付范围，但不再作为运行核心日用的先决条件。实际施工与资格从源码/来源票和 LIVE 读取，规划不授予现役采用。

本轮运行文档检查和差异检查。后续实施需验证实际 parser/API、同键重试、回执丢失、并发修改、快照/事件缺口、数据源读写、独立进程寿命及迁移。离线测试、Node 制品、真实 Gateway/Host 和浏览器验收分别记录；文档通过不证明功能交付。

全产品验收以新版已接受能力为范围，不以当前代码已有多少反推承诺。核心范围先按上述采用门验收，未包含的全产品义务保持未完成，不改成全局 excluded/passed。自有 Web 功能版完成真实浏览器、安全与共享后台 E2E；视觉定稿后补体验验收，不重跑无关模型矩阵。上游能力不足导致接受目标无法兑现时，明确保留实现/资格阻断并对齐承诺，不能自行改成可选项。[LIVE](../../tickets/LIVE-integration-validation.md)维护唯一集中验收清单与结果，旧窗口证据仅支持其原版本和范围。停用、安全恢复或回官方与恢复旧开发版连续服务是不同要求；不要求通用旧版本降级，但也不授权任意修改现役或清理原生资料。

## 独立后续范围：语音委托

[Box-only 语音委托 Spec](../voice-delegation-spec.md)保存当前手头阶段之后回访的已接受方向：已经委托到 Box 的语音请求复用原生 Bot 的模型选择、上下文、执行与结果渠道，不另建 Agent loop，不修改官方客户端，也不承诺每句实时语音都经自定义模型。研究线索、工程边界和具体验收由该专用 Spec 及 [VOICE 来源票](../../tickets/README.md#voice-delegation)拥有。

这项增量不改变本 Spec 当前 W1–W5 完整交付范围、HOST-01 优先顺序或既有 LIVE 门槛；不要求 CLI/Web 增加通话入口。后续启用时以最新共享后台、模型接缝和 Host 资格为基础，专业问题优先委托的角色策略仍单独评估，不作为已经承诺的强制路由。

## 变更规则

已确认目标直接写回对应正文，未决项留在决策清单与来源票；不另建竞争版本。有明确合理默认解的工程细节直接收口并验证；涉及产品范围、核心体验或真实能力不足导致承诺变化时再对齐。固定研究和 review 报告保留原窗口，本轮决定写入活动文档。实现采用后，再把长期合同归入产品、架构和 runtime 的现行正文。
