状态：2026-09-26 用户接受的实施次序调整，尚非正式产品实现或新现场验收。Local-first 已有[固定历史正例](../../archive/box-local-first-poc-2026-09.md)，因此恢复 Agent First CLI/v2 产品施工，不再等待“永久不迁移”或全部升级路径证明。普通官方升级导致失权的反例及额度未知继续保留，不能因此宣布日用或全产品已通过。

本页只拥有本次增量的阶段与责任；[Spec](spec.md)拥有完整产品目标，[并行交付](parallel-delivery.md)拥有原 A/R/F/E/D/B/C/W/Q 路线，[CLI-05](../../tickets/CLI-05-implementation-follow-through.md)拥有整体收束，[LIVE](../../tickets/LIVE-integration-validation.md)仍是唯一现场状态入口，Linear 负责排程。

## 1. 两条工作线，不降低最终目标

**主线：把成功的 Local-first 机制变成正式 v2 产品入口，恢复原架构收束。** 继续复用共享 client/管理 Server、领域操作与回执、独立 modeld、原生状态 writer、逐 Bot 模型选择和上下文能力。POC 证明的是可实现性，不把临时硬编码目录、另一个状态库或直接写 Host 的实验加载器变成正式架构。

**并行支线：持续观察身份改变，识别驱动因素及可维护的更新策略。** 先交付可消费事实和缺口，再根据正常接口及实际许可评估预防/恢复；不要求取得员工内部诊断才允许主线施工。发现真实失权仍须停止那个身份的受管执行，不能以“支线”取消安全责任。

不修改官方 App；普通私聊、多群成员、Bot 自身 Routine、统一身份/长期 Memory、按会话区分上下文、逐 Bot 自定义模型与官方对照仍是目标。不得用单人群、独立聊天页面或官方模型工具委托替代。能创建只解除产品研发的全局阻断，不等于后续验收自动通过。

## 3. 正式创建的最小产品边界

调用者继续使用当前正式 `bot create` 合同，不暴露“先改文件、再调登记、再补台账”的内部步骤。共享管理领域拥有授权、请求身份和结果；原生 adapter 在当前已验证来源上完成本地工厂与登记的实际顺序。原生 writer 拥有真实资料和服务端绑定，不通过修改本地 harness 冒充 Server 接受。

复用原 `PatchProfile` / `applyPatchProfile`、来源保全和已存在的 controller/采用机制。新增切口纳入当前 recipe 和有限 AST/角色检查，默认/Temporal 分支与未选目标保持原合同。移除已被新实现取代的错误创建分支，不新增长期双 writer 或 CLI 直连 fallback。

将 POC 的有价值合同按职责吸收：原 ackToken 随回复传递；Routine 子任务经原 settlement/automationParentWake 回父 Bot；Memory 沿原生 owner；选择及在途捕获沿既有运行核心。是否需要局部执行适配由实际缺口决定，不把临时 POC Loop 整份复制来绕开现有 compact/checkpoint/modeld。

创建、独立归属、可执行、模型运行、显示和清理分别给出事实。创建未知或服务端返回不符时保持原请求与准确身份，不换 nonce 重发、自动找别的对象代签或偷偷转 Temporal 模型执行。

## 4. 创建源头健康：三种验证，各守一层

| 层 | 验证内容 | 不能推出 |
| --- | --- | --- |
| 形状与语义 | 当前源/worker 与 recipe；AST 角色、控制流、字段转发和变换后原声明；合法负例 | Server 仍接受本地登记、现役实际调用了切口 |
| 实际加载与使用 | 候选制品、已加载 Host/helper/来源与运行代；真实创建经过的有限边界 | 收到 HTTP200 就是 Box、旧窗口可覆盖新来源 |
| 真实创建 canary | 正式 CLI 到原服务端登记，一只静默普通 Bot 的首次结果、独立 Server/local 读回及原生清理 | 普通模型/DM/compact已通过、身份永久不变或账单为零 |

哨兵只为核心依赖提供快速信号，不成为新型全仓验证框架。将 last success、last attempt、来源/候选/账号作用域、新鲜度及失败阶段分开；显示通过、失败、不确定、未运行/过期，不能把 no-run 默认为健康。清理失败不倒写创建失败，也不能抹掉未收场的测试对象。

**早期触发**：相关创建代码或配方集成后，在一个具备明确授权的实际候选窗口先运行；实际加载来源变化使旧结果过期。不要等双 Bot DM/真实 compact 才发现登记失败。

**持续触发**：Host 来源不变时 Server 也可能改规则，因此在维护者明确启用的 canary 环境支持低频周期验证；有新来源/相关同形变化时合并触发，不每次提交、每次健康查询、每个普通用户启动都制造 Bot。任务由现有验证/管理寿命承接，不新增定时平台。公开 CI 仅运行可公开隔离用例，不访问私有 Host/账号。

**安全与资源**：一个预声明 request-id、一个准确测试身份、禁止 introduction/kickstart、不调模型、不建群和 Routine；创建后独立读回，再清理准确已知自有对象。无授权则不发起写入并标明缺口；超时/账号不可达、Server拒绝、形状失配、加载错误、结果不符和清理失败分别记录。未知效果先对账，禁止用批量重建掩盖失效。

**失败影响**：暂停依赖该失败来源的创建动作及相关发布/验收，保留独立工作；不关闭已获准且健康的在途模型工作，不阻止无关架构/文档/Web 开发。可见失败沿原 OBS/incident/outbox 送往普通用户和指定维护 Bot，不因无维护 Bot 而丢失安装级观察。

## 5. 身份变化支线与更新节奏

AH-193 在现有 HOST-01/T44/OBS 中关联 Host 来源/loaded generation、版本动作、可读的原生操作结果、原 Server 身份和本地投影。优先覆盖新运行代最初阶段，区分已发生的变化、源码候选关系、读取陈旧和缺失历史。文件 mtime 不是服务端迁移时间，相关不等于因果。

相关同形变化需要分析，结构破坏和真实创建/身份失败需要告警；未知可以尽力而为，但不得被写成通过。普通用户感知、维护 Bot 任务、候选修复及采用都复用原责任链，不为本次事件新造 collector、数据库、通知引擎或业务 Agent。

AH-190 继续评估正常维护窗口和预授权采用：上游发现、候选准备、自动切换是不同职责。延迟自动更新不等于永久冻结，不会撤销已暂存命令或外部更新，也不保证服务端身份数日不变。正式支持范围要披露真实控制边界；更新涉及的 Host/worker/source、原 supervisor 与恢复分别核对。该研究不是当前开发的全局前置，也不能伪造官方身份/迁移完成、绕过权限或以关闭同步维持假象。

已有资格的恢复分支不天然等待 AH-189 写代码；确实需要改 recipe/adapter 的分支才消费其候选。最后 AH-191 验证承诺范围的维护连续性与用户通知，不要求证明所有未来版本。

## 6. 历史归档、临时资产与并行规则

本次主题归档为[普通 Box Bot POC 精华](../../archive/box-local-first-poc-2026-09.md)。`docs/reports/` 保留原固定窗口与已有链接；LIVE 只维护当前摘要，不继续在顶部堆叠相互冲突的历史停点。

当前只归档精华，原 POC 暂留：受控窗口 helper、创建流程、原始 Server 响应和已修 ack/Routine 是集成输入；仍在推进的后续 program-update 实验也不属于本次删除范围，其新结果不能混入固定历史窗口。先解除跨目录 import、迁移独有证据并核对摘要/读回/无活动使用，再由 AH-194 清理可再生及不再引用的临时资产；unknown、原生资料与现役资源不因归档被删除。

按实际文件/合同并行：D/A 联合拥有创建，Q 与其并行接哨兵；E 只读采集和通知，F 受控维护，B/C/W 继续原路线。一个 worktree 一个写者，Host 现场只有一个操作者；新功能从当前 v2 切短分支并线性回流。新文档与排程不授予 live 创建、升级或批量清理权限。
