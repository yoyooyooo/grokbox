# 命令收束决策清单

本页记录已确认目标与剩余合同问题。架构和核心能力经过本轮 grilling 对齐；参数、状态码等细节暂缓。接受目标不代表已实现，也不把 review 建议自动视为用户决定。

## 已确认方向

| 编号 | 决定 | 来源与作用范围 |
| --- | --- | --- |
| A01 | 主要调用者为 Bot 与代表用户工作的 Agent | 本轮会话；能力表达、命令和参数优先稳定的机器合同 |
| A02 | 期望破坏式重建，由命令收束反推实现与架构 | 用户明确项目尚未正式发布；无需保留旧模块或旧语法，不等于丢失必要数据和能力 |
| A03 | 一个 grokbox CLI，gbox 等价别名 | 内部进程可以按职责和寿命分化 |
| A04 | TanStack Start 前端，业务 API 为独立 Effect v4 beta、Effect-first 服务 | SSR 仅页面预取/渲染；前端放在 MonoRepo apps 子项目 |
| A05 | Web UI 以内部观察为主，并承载必要管理操作 | 模型、保护、数据管理与异常处理共用后台用例；首版无聊天/业务任务发起/审批回复 |
| A06 | 最后一批视觉稿保留为 V0 参考，最终风格未定 | 不冻结配色/造型或作为功能施工前置；图片中的功能不自动获准，原图与缺失情况如实保留 |
| A07 | CLI 合同是前置，整体规划覆盖重建至 Web UI 完整交付 | 用户后续扩大规划范围，取代最初的实现占位；本轮仅更新规划和验收工具，不启动业务重建或现场采用 |
| A08 | 提供基础能力，使用策略交给调用者 | 不内置 Bot 分工、通用任务/DAG 调度或第二 Agent loop；保留真实原生协作/Routine 能力 |
| A09 | 真实 Bot 为主体，只保留保护与交接所需关联 | A/B 各有原生身份；不引入独立跨工具人格、身份规则与 Memory 身份层 |
| A10 | 所有确认 Box-owned Bot 默认保护，可逐 Bot 调整/关闭 | 默认观察与材料保全；无需另行登记为一种伙伴身份 |
| A11 | 后台负责按证据推进重建与交接 | 确认官方回收才进入替换；断连/陈旧不足以证明归属丢失；Bot 判断与实际回执分开 |
| A12 | 一个常驻管理服务，modeld 独立进程 | 管理服务内模块/worker 分别承载采集、证据、索引、异常、保护、交接和通知；重启不主动终止已开始的合法 modeld 执行 |
| A13 | 普通 CLI/Web 业务共用后台 | bootstrap/生命周期、离线诊断与外部 Box 恢复为明确例外；不隐式直连业务 fallback |
| A14 | 后台持久保存必要观察记录与来源证据 | 历史覆盖实际采集范围；stale/gap/unknown 不伪装实时或健康 |
| A15 | 全局 Memory、Project 文件提供跨授权来源检索 | 可重建索引不接管原始内容；保留来源、scope 和覆盖 |
| A16 | Bot 可原生、跟随默认或指定模型 | 只有明确跟随者受默认切换影响；显式指定相同模型也仍为指定 |
| A17 | 指定模型跟随该模型自身配置更新 | 后续轮次采用更新、记录实际版本；普通配置修改不改写在途捕获事实 |
| A18 | Memory、Project、文件纳入读写能力范围 | 按来源验证写入路径与结果；缺可靠写能力的来源只读；精确写动作仍待收口 |
| A19 | 后台主动跟踪管理异常，通知显式启用后自动投递 | 去重、有限重试、投递记录归后台；ack/忽略不代表恢复，投递成功不代表异常解决 |
| A20 | 新命令面直接切换，旧语法无对外兼容期 | 同批迁移仓内和已知调用方；可以分阶段施工，最终只留一套正式语义与 writer |
| A21 | 在用模型与默认设置先解除引用，再删除/清空 | 拒绝删除仍被 Bot 选择或全局默认引用的模型；仍有跟随者时拒绝清空默认，返回引用关系，不擅自换模型 |
| A22 | 通知测试独立、显式且可选 | 完成必要配置和授权后可显式启用；测试不是启用门槛，启用/测试/实际投递分别记录 |
| A23 | 有明确合理默认解的工程细节直接收口 | 用户授权无需逐项拍板；改变产品边界、核心体验或因真实能力不足调整承诺时再对齐 |
| A24 | CLI/Web 复用领域能力、共享合同与客户端 | Web 不执行 CLI 子进程；展示与聚合可独立，领域规则只有一套；命令树不决定模块划分，不机械拆微服务/小包 |
| A25 | 完整目标不变，运行核心可先独立验收采用 | 2026-09-22调整原一次性全产品采用顺序；未采用施工版可不完整/不可用，不建迁移期双轨；已采用核心固定制品与后续开发隔离，见A31 |
| A26 | 保留原生数据及身份，旧开发期内部历史不承诺导入 | 配置按需一次性转换，投影/索引重建；不建设通用历史迁移框架，不授权自动删除源数据/凭据/旧状态，也不放弃新版必要历史 |
| A27 | 规划先固定核心方向、边界、骨架和故事 | 具体包名、schema、路由、组件及施工细节由实施者按原则决定；本轮目标包括安装、浏览器和最终验收 |
| A28 | 自有 Web 功能/视觉可并行后置，仍完整交付 | 2026-09-22明确不阻运行核心日用；已建apps/共享API/真实页面保留，安全不降低；原版Grok Bot App仍是核心必验 |
| A29 | 核心与完整产品分别冻结、工程验收和用户确认 | 核心在W3内部完成适用检查/独立审查、真实模型/App/持久恢复及持续运行后可日用；全产品继续W4/W5，不用局部绿色或用户代测放行 |
| A30 | 新版验收按接受目标重定基线 | 原生数据和运行可靠性继续保护；旧开发版连续切换及通用降级不再是门槛，旧证据不继承为新通过；正式发布另行授权 |
| A31 | 将运行核心日用节点前移，但不降低质量 | [Spec核心采用](spec.md#core-runtime-adoption)；受控切Host/modeld先于核心日用，正常辅助链/长上下文/原版App/必要保全/重启与退出不可排除；核心未覆盖的全产品义务不改optional |
| A32 | v2唯一集成线，多worktree按完整出口阶段性回流 | [并行拓扑](parallel-delivery.md)；先合已提交成果与排程，保留桌面/VOICE未提交；新分支从v2切出，单worktree单writer，合并不自动采用或发布 |

A09 撤回了先前将接替关系提升为独立持久身份的提议。A08 撤回了把“Bot 如何自助、创建其他 Bot、分工”作为内置产品使用策略的提问；这些意图由基础能力支持，具体组织方式不由 grokbox 规定。
