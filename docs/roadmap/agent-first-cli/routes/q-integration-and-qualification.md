# Q · v2 集成、候选资格与采用窗口

归属：[并行拓扑](../parallel-delivery.md)。Q是集成/验收责任，不是第九个领域重写分支；v2工作树只有一个写入者。独立review必须由未实现相应工作包的审查者完成，Q不得把自检改名独立审查。

## 先读与当前优先结果

先读[Spec的核心采用边界](../spec.md#core-runtime-adoption)、[拓扑汇聚点](../parallel-delivery.md#joins)、[CLI-05](../../../tickets/CLI-05-implementation-follow-through.md)、[核心LIVE集合](../../../tickets/LIVE-integration-validation.md#core-runtime-lane)、[执行手册](../../../maintainers/live-end-to-end.md)。先推进J2→J3→J4，不继续按所有管理命令族串行施工到全产品结束才验运行核心。

## 集成职责

J0先将已提交管理成果和本波文档线性合入v2；现有桌面未提交工作及VOICE规划单独保全。核对v2工作树、ahead/behind与未提交内容，不能直接提交整个index。新开发路线从实际v2 tip切worktree；每次A1/R1等可验出口回流，不等全路线。

实施者先rebase当前v2、解决本域冲突并复验，Q串行快进。共享Server/client/CLI/Web装配只做必要冲突整合，检查路由/权限/回执/关闭顺序和旧writer去向；没有文本冲突不代表组合正确。根依赖/lock与总验证清单由Q集中管理，不并行执行互相覆盖的升级。未取得工具实际成功回执不声明合并完成。

旧并行成果由对应owner内容级吸收；无法证明等价或缺共同祖先时保留分支/工作树，不盲合、不删除。文档历史不作为代码正确性依据，也不要求为每份旧报告重新关闭全部历史工作。

## 各汇聚点的工作

| 点 | Q必须组织的结果 | 不允许的替代 |
| --- | --- | --- |
| **J1** | 逐接口登记生产者/消费者、合流提交、原生资格/错误/读回合同和所解除的出口 | 一个“等A全部做完”的全局大锁 |
| **J2** | A2/R1/F1/E1/D1合入同一候选；必要B/C修复纳入；适用检查、实际安装、独立审查、真实宿主、风险闭包、保全/恢复及窗口授权齐备 | 测试数量、parse、profile保存或Git合并作为采用许可 |
| **J3** | 按核心LIVE集合执行实际采用/加载、R2模型与App旅程、故障/权限/非干扰、重启/官方退出、至少24h有界观察及资源收束 | 先让用户日常使用，再拿这段时间补基本工程验收 |
| **J4** | 汇总固定运行制品、支持模型/Bot/行为、未采用功能与风险、清理/恢复证据，取得用户对核心范围的明确接受 | 代用户签字、全产品passed、自动公开发布 |
| **J5及W4/W5** | 汇合后续全功能与旧入口退出，做完整产品验收和最终呈现 | 以核心日用为理由删掉B/C/W等已接受义务 |

## 核心候选风险闭包

必须核对实际加载的补丁和启动的所有worker，而非只看用户会点击什么。核心涉及的原生Memory/episode、工具/辅助调用、checkpoint、默认观察/必要保全、配置导入、未知效果及故障恢复均不可排除。自动替身/退役/通知/桌面等若未资格化，须有原owner的真实权限/策略隔离和不干扰证明；不能仅关页面、默默降低保护或手清状态。

首次采用前可用隔离原生/制品/恢复资格，实际loaded和真实业务证据在首次采用后生成；不要制造循环门。Host是共享故障域，必须核对非目标Bot、官方passthrough、启动同步和旧在途影响。没有具体恢复能力不得先停现役再研究。

## 验证与有限审查节奏

领域提交跑本域及直接交叉回归；合流窗口跑组合检查；J2固定候选再收口适用整体检查、打包、隐私与独立审查。源码、制品、配置/原生依赖分别记录，文档或纯格式变化做相应复验及影响说明，不为每次修改重复全部原生/Chrome。既有证据能否复用取决于依赖是否变动，不按“最新一次绿色”无条件继承。

review关注真实产品不变量、权限/恢复/资源和可执行验收。完成一轮修复及针对原发现的复查后，非阻断额外改进回来源票，不无休止扩边；P0/P1、安全/data损坏/重复效果和必需能力缺口仍阻J2/J3，不能为节奏豁免。

只读`verify:live-window`的candidate/plan检查是规划工具，不签采用就绪。现场动作使用仓内live-validation Skill并核对有效目标/费用/停止/保全许可；不得从旧报告授权推导新操作。各路线只向Q交明确需求，不能各自切同一个Host或重启日用modeld。

## 运行与开发隔离

Q限制同Box重构建/Chrome并发，各路线使用独立测试根/端口；实际Host/账号/原生写只有一个窗口。长时测试使用有限期限、真实负载/维护周期和可观察回执，工具失联不推定成功，不以后台承诺替执行。

J4后运行固定不可变安装制品；v2继续向前但不触碰现役preload、modeld、Rust binary、配置或全局shim。下一次日用升级从新v2候选重新核对受影响门，不从施工worktree直接采用，不新增旧新执行兼容层。

## 回执与阻塞处置

路线回执包含base/tip、模块/合同出口、实际验证及真实性、原生/配置依赖、旧入口处置、直接消费者、剩余阻塞/下一出口。只维护来源票和LIVE的对应事实；CLI-05写短的汇总定位，不继续追加大量互相覆盖的历史测试计数。

阻塞写成`类型 → 所缺对象 → 生产owner → 消费出口 → 解除证据`。ENV/TOOL/AUTH仅阻受影响操作，其他可施工路径继续；资格不足不等于所有源码不可做。用户简报首先回答是否到J2（可受控切Host/modeld）、J3（工程验收通过）、J4（可日用），再说明本次合流和剩余关键路径。
