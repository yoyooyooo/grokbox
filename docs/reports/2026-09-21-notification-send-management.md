# Explicit notification delivery through management

2026-09-21. CLI-05 W3, T45/T46/T54/T55 and WEB-03. Continues the existing management branch and original OBS outbox; not W4 candidate acceptance or permission to send a real notice.

## Current owner and contract

`notification send` submits an existing installation/database-scoped incident work reference, the exact receiver reference, reviewed binding/model revisions, a persisted request UUID and explicit cost confirmation. `notifications.send` is independent from read, test, enable and pairing rights. CLI and Web use the same management program. `operation get --domain notification --database-id … --request-id …` reads the original principal's request without consulting current configuration or native sources. There is no arbitrary body, URL, credential, test-work or Gateway fallback.

The original observation database now declares schema 5. Its `notification_sends` rows bind principal/request intent to the existing work and original attempt. New initialization creates the complete current schema; old schema 4 remains preserved but unsupported, without automatic migration or replacement. CONT and Routine schema versions do not change. Claim publication precedes invocation, and linking a management request to an actual attempt occurs in the original reservation transaction. Automatic workers exclude claimed work; a different UUID, caller or alias cannot inherit the first invocation or attribute somebody else's previous delivery. A lost claim acknowledgement remains unknown even with no attempt yet. A zero-dispatch refusal is recorded only by the original invocation, not inferred by reconciliation.

Delivery still uses `runOpsNotificationDelivery`, the original private credential owner and native HTTPS adapter. Binding/model/ownership/policy, ongoing send authority and budgets are checked at the relevant boundaries; no local lock or SQLite transaction spans HTTP. Client disconnect does not cancel a submitted server operation. Shutdown aborts and awaits original network/commit settlement. Hard death never authorizes another POST. HTTP acceptance, Bot report and user-read remain distinct. Definite-rejection retries, upstream reconciliation and safe long-term receipt retirement remain T45/OBS-05 work; this implementation does not invent them by retrying.

The former `ops notifications send/list/show` registration, CLI writer and standalone explicit-send/status facades are removed, with consumers moved to current management or original-owner tests. The fixed transport and outbox algorithms are reused, not copied.
