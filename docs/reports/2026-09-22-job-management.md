# Managed Jobs and retirement of daemon execution

CLI-05 W3. Builds on the [original resource-owner extraction](2026-09-22-job-owner-foundation.md). This work moves the complete ordinary Job entry to the existing management Server/CLI/Web, not a second executor. It does not sign W4, whole-installation adoption or complete file/material migration.

## One current execution owner

The Server's Effect Scope acquires the original Box Job manager and its governed filesystem/process authority once, independently of each HTTP caller. The original named-root descriptors, executable aliases, literal argv, minimal environment, process-group identity, queue, deadlines, bounded output and durable per-Job records remain in that owner. No new database or generic workflow engine is added. The existing canonical process/filesystem policy fields are still the source; their `daemon` configuration namespace is not permission for the retired daemon to execute.

`job policy/start/list/get/wait/logs/cancel` and `operation get --domain job|job-cancel` use the shared browser-safe client. Ordinary `exec run`, `jobs ...`, five daemon Job RPCs, daemon startup/close ownership and CLI execution implementations are removed, not forwarded or retained as refusal-only handlers. Unmigrated file/desktop/Gateway capabilities keep their own paths and do not regain Job execution.

New requests bind installation, actual principal, caller-persisted UUID and a reviewed service/policy revision. The deterministic Job identity and canonical input digest are stored before spawn. Another principal cannot read or cancel it; another input cannot reuse it. Repeated original requests read history before consulting a changed or unavailable current policy. New work requires separate start/shell rights, and queued work rechecks live authority and policy at actual dispatch. Read, output, cancellation and operation history have independent grants. Input and browser recovery data do not persist argv/environment secrets as receipt metadata.

Only the current scoped record and service-generation format is consumed. Old or corrupt records stay untouched and block execution acquisition; they are not upgraded or overwritten into a fresh history. Exact record, scope, command and log fields are required: retired generation fields, missing scope and extra top-level/nested data are rejected by both cold reads and owner acquisition while preserving the original bytes. Diagnostic retention no longer erases replay guards; safety-record capacity refuses new admission. Logs retain bounded bytes, continuation offsets and explicit gaps. Unknown execution never means a completely observed output stream.

## Publication, cancellation and lifetime

Per-Job state publications serialize in the original writer. Parallel retained reads await the current publication rather than signing an in-memory admission. A deterministic real-HTTP test subsequently found that the list path still projected an unpublished in-memory terminal while the exact read waited. Both now use the same stable record: the original writer's completed publication result, captured only after its own file/directory sync, so a newer in-memory write cannot overtake the publication being awaited. An intermediate fix that reopened the active writer's file exposed a source-unavailable read during its next atomic replacement; active observations now avoid that self-race. Cold or borrowed history still uses the strict physical reader. This adds neither another store nor a truth inferred from current process state. Known local uncertainty still overrides older successful bytes. A held-terminal publication test and forty concurrent list/exact-read rounds during real log publication exercise both boundaries. A lost admission acknowledgement keeps the identity occupied and does not spawn. A lost queued-cancellation publication, even after the actual commit, never requeues the task or releases its cancellation identity to a different request. Running cancellation uncertainty is also not another caller's permission to signal.

The management service owns execution after client disconnect. Graceful shutdown aborts pending authority, settles actual processes and local writes, then releases the physical owner gate. Even a failed shutdown publication cannot release the gate ahead of pending execution. A separate packed Server killed with SIGKILL leaves started and queued Jobs unknown after restart, with no automatic re-dispatch. The disposable started process in that test is explicitly released by its original fixture and ends; no guessed production PID is signalled.

The boundary is deliberately narrower than an OS sandbox or external transaction: an approved executable runs as the service user, cwd does not confine its effects, cancellation does not undo files/network effects, and Node process-group checks are not pidfd-atomic signalling or proof that arbitrary escaped descendants ended. Arbitrary deletion/rollback of all safety identity footprints is not made recoverable by this migration. Safe lifetime retirement and whole-installation qualification retain their existing responsibilities.

## Web and verification

`/jobs` supports policy review, strict structured input, explicit execution confirmation, principal-local list, selected observations, explicitly requested binary-safe output, cancellation and original-request recovery. The shared operation page supports both Job domains. Browser storage holds only installation/principal/request/target locators, not command input, reusable approval or credential data. Known admission is marked `recorded`, not successful execution; unknown locators cannot be discarded or replaced by refreshing. Revisions and drafts remain separate, output is rendered as data, and writes still require current authentication and CSRF.

The initial Node management suite passed all ten scenarios. After adding publication/cancellation guards and a real packed-Server hard-exit scenario, one intermediate window lost an HTTP reply around restart; it was correctly reported as operation_unknown. A later diagnostic run observed an ECONNRESET on the one POST immediately after listener restart. The client correctly classified that lost transport as operation_unknown. The ten-installation regression now requires either the exact historical reply or that specifically observed reset plus the original unknown locator and independent GET readback; it never repeats the POST to obtain green. Other failures still fail the test. This does not claim to eliminate connection-loss risk or add a production retry. The first browser run exercised all Job actions but failed the new fixture's zero-native-read assertion because the login landing overview had already performed its own Bot-list read. The fixture now captures that landing count before entering Jobs and asserts Jobs add zero reads; no product authority or browser mutation assertion was relaxed. The previous timeout fixture combined the original five-second termination grace with another cleanup grace; it now waits for the second short Job's actual terminal before cleanup, without increasing its deadline.

The enlarged browser inventory exceeded its original 150-second aggregate parent deadline. It is now partitioned into disjoint console/state/Host windows, retaining the existing per-window and per-scene deadlines and zero-skip checks. The Node browser suite runs without a redundant isolation child, not with force-exit; tests still have to finish and release their resources. The old expired browser fixture processes were identified by their exact workspace, artifact path and parent relationship and retired without signalling a Host or business Job. One Compact test also raced router invalidation by reading a retired CDP response body to format a passing assertion; its oracles remain the real response status and the independently read revision rendered in the page, without that unnecessary body read.

The expanded core run then found three CLI tests depending on an ambient live Host generation. Those unqualified-apply cases now explicitly supply the observed-generation input while still executing the original controller and asserting zero mutation. A separate absent-generation case proves refusal before desired-state or files change. The production admission gate was not relaxed, and none of these cases signs live adoption.

The stale Profile process-capability claims and unused daemon Job publisher/source were also removed. Job lifecycle/output observation belongs to the new principal-scoped get/wait/logs APIs; other domains' global event convergence remains CLI-03.
