# CLI-02 · 提交变更、丢失回执并恢复查询

状态：模型关系与后台边界已接受，提交/恢复/采用的精确协议待细化。依赖：[CLI-01](CLI-01-discovery-and-targeting.md) 的引用、输入与调用身份合同。本票完成不代表实现交付；当前不启动代码搬迁。

## 用户结果

Agent 为 Bot 选择原生、跟随默认或指定模型，提交后连接断开，仍能找回同一操作。显式指定者不随默认切换，但其模型自身配置更新作用于后续轮次。调用者区分配置提交与实际采用，不把当前 TURN 的历史选择改写成新配置。

## 方案范围

收口[决策 D04、D05、D06、D08](../roadmap/agent-first-cli/decisions.md)。以模型选择和 Bot replace 两个真实用例确定 request-id、指纹、plan、提交、领域 revision、未知结果、取消/恢复和采用回执。把服务自身启停作为目标服务不可达时的边界案例。一个常驻管理服务、独立 modeld、普通 CLI/Web 共用后台及明确恢复例外已确定，不重新讨论是否隐式 fallback。

## 验收产物

- 定义哪些提交必须提供 request-id，preview/refresh/进程寿命如何例外，记录过期后旧请求如何拒绝。
- 同键同输入、同键不同输入、接受前失败、效果后回执丢失、跨进程重启及迟到结果均有状态与下一动作。
- plan 绑定目标/版本/有效期但不授予权限；提交重新核验，拒绝不产生业务写。
- operation 状态与领域步骤结果兼容，索引不夺取原领域账本；部分完成和 unknown 不自动重发。
- 配置 commit 与未来 adoption 分开；覆盖跟随默认、显式指定同一模型、模型自身配置更新、在途版本保留；client timeout/Ctrl-C 不取消已接受业务。
- 默认保护和交接按证据推进，Bot 辅助判断与真实执行回执分开；目标可用、关系迁移和可退役分别验收，不把未知效果重新提交。
- 原生 CAS 不足时明确 local_serialized/best_effort 范围；不把本机锁写成官方 App 的并发保护。
- 自身维护与停止 server 的回执不依赖被结束的调用者；无法保证时说明 unsupported/blocked。
- 首个 CLI/浏览器共同写用例即覆盖重复点击、页面刷新、会话过期和响应丢失；请求与回执绑定同一原操作，认证恢复不暗中再发。R01/R05 不拖到最终页面或旧版本完整 LIVE 之后才验证。
